# プロライン → 鈴木薬舗OS 移行方針

作成: 2026-09-04 / 決定者: KOTA（鈴木賢太郎） / 記録: Claude (Opus 5)

## 0. 決めたこと

**鈴木薬舗OS を主にする。ただし段階的に。プロラインは解約せず残す。**

背景は `HANDOVER-2026-09-02-claude.md` 第10章。リッチメニューを
プロラインとOSの両方が書きにいっていたため、既存のお客様と新規の方で
表示が食い違った。原因は設計ではなく **持ち主が決まっていないこと**。

## 1. 原則（これを破ると同じ不具合が再発する）

1. **1つの機能の持ち主は、必ずどちらか一方。** 半々にしない。
   「移行中だから両方」が今回の不具合そのもの。
2. **可逆であること。** LINE 側のリッチメニューは削除しない（unlink / link で切り替える）。
   プロライン側の設定は変更前の値を必ず記録してから変える。
3. **本番へ触った操作は日付・値・戻し方を記録する。** 記録先は HANDOVER 文書。
4. **お客様に見える変更は、下見（dry run）→ 実行 → 実機確認の順。**

## 2. 段階

### Phase 1 — リッチメニュー（着手中）

- 持ち主を **OS** に確定する。
- プロライン側のリッチメニュー指定を**全てオフ**にする。
  「プロラインの基本リッチメニュー」は 2026-09-02 に `LINE`（なし）済み。
  **残: 超ステップ配信のシナリオ単位「このシナリオ登録時に適用されるリッチメニュー」**（未確認）。
- 既存のお客様に残っている個別割り当てを外す
  → `POST /api/line-accounts/:accountId/rich-menu/unlink-all`（コミット 8096625）。
- 完了条件: 既存のお客様・新規の方の両方の実機で、同じ新メニューが出る。

### Phase 2 — 自動応答と入力の削減

- リッチメニューから「お客様が文字を打たないと進めない」経路を無くす。
  （9/2 時点で、フォームURLの誤り・auto_replies が 0 件の message ボタン、を確認済み）
- 持ち主を OS に。プロライン側の同等設定はオフ。
- 完了条件: メニューの全ボタンが、打鍵ゼロで目的の画面かトークに着く。

### Phase 3 — シナリオ／ステップ配信

- **一番重い。まず数えてから決める。**
  プロラインに生きているシナリオ・ステップ配信の本数と中身、
  OS 側 `scenarios` / `automations` / `auto-replies` / `reminders` の中身を対照する。
- 内容は薬局の判断が要るので、機械的な移植はしない。
- 完了条件: 未定（Phase 3 着手時に決める）。

### Phase 4 — 予約

- 現状は並行期間。プロライン予約は `external_bookings` に取り込み、
  OS 側の空き時間計算と二重予約チェックに反映済み（コミット e0b9839）。
- 予約の入口を OS に一本化できた時点で、取り込みは不要になる。

## 3. 移行しないもの

- **相談カルテ・注文台帳・動画ライブラリ**は最初から OS のみ。プロラインに対応物なし。
- **プロラインの過去ログ**は移さない。参照用に残す。

## 4. 未確認（推測で埋めないこと）

- プロラインのシナリオ単位リッチメニュー指定の有無と件数。
- プロラインに生きているシナリオ・ステップ配信の総数。
- OS 側 `scenarios` / `automations` テーブルの本番の中身の件数。
- プロラインの契約・課金条件（解約可能時期など）。
